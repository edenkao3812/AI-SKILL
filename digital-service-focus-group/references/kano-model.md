# KANO 品質分類與問卷判定規則

本參考依使用者提供的兩張資料圖整理：第一張為品質具備程度與滿意度曲線，第二張為正向／反向成對問題的 5×5 判定表。

## 目錄

1. 品質曲線的五種類型
2. 成對問題
3. 5×5 判定矩陣
4. 焦點小組中的使用規則
5. 剛性需求與理想需求係數
6. 報告要求

## 一、品質曲線的五種類型

橫軸表示服務功能的具備程度，由「非常欠缺」到「具備程度高」；縱軸表示使用者感受，由「極不滿意」到「滿意程度高」。

| 代碼 | 品質類型 | 曲線與經營意義 |
|---|---|---|
| A | 魅力品質 | 沒有時不一定不滿；具備時會帶來超出預期的高滿意。適合創造驚喜與差異化。 |
| M | 必要／當然品質 | 沒有時會非常不滿；具備時只被視為理所當然。是進入市場的基本門檻。 |
| O | 一元化品質 | 功能表現越好，滿意度越高；表現越差，不滿越高。適合成為可量化的競爭指標。 |
| I | 無差異品質 | 有或沒有，對滿意度影響都有限。通常不應優先投資。 |
| R | 反轉品質 | 功能越多或越強，部分使用者反而越不滿；應檢查是否需要關閉、選配或分眾。 |
| X | 無意義回答 | 正向與反向回答組合矛盾，無法形成有效品質判定；不是品質曲線類型。 |

本 Skill 先以 A/M/O/I/R/X 呈現各角色或受訪者的判定，再計算剛性需求與理想需求係數，透過四象限圖決定重要性與優先順序。

## 二、成對問題

對每一項服務功能分別提出：

1. **正向問題：**「如果本服務具備［功能］，你的感受是？」
2. **反向問題：**「如果本服務不具備［功能］，你的感受是？」

兩題都只能選一個相同尺度的答案：

1. 很愉悅
2. 理所當然
3. 沒感覺
4. 可以忍受
5. 無法接受

不要把「反向問題」誤解為反轉品質。反向問題只是詢問功能不存在時的感受；是否屬於 R，必須依成對回答矩陣判定。

## 三、5×5 判定矩陣

列為正向問題答案，欄為反向問題答案。

| 正向＼反向 | 很愉悅 | 理所當然 | 沒感覺 | 可以忍受 | 無法接受 |
|---|---:|---:|---:|---:|---:|
| 很愉悅 | X | A | A | A | O |
| 理所當然 | R | I | I | I | M |
| 沒感覺 | R | I | I | I | M |
| 可以忍受 | R | I | I | I | M |
| 無法接受 | R | R | R | R | X |

Legend:

- `A`：魅力品質
- `M`：必要／當然品質
- `O`：一元化品質
- `I`：無差異品質
- `R`：反轉品質
- `X`：該回答組合無意義

## 四、焦點小組中的使用規則

### 有真實問卷資料時

1. 逐位受訪者、逐項功能套用矩陣。
2. 統計 A、M、O、I、R、X 次數。
3. 以有效回答中出現最多的類型作為主要結果。
4. 將 X 排除於品質類型比例之外，但報告 X 的數量與比率。
5. 若前兩類票數相同或接近，不要擅自強迫分類；標示「混合／待追加樣本」並呈現分布。
6. 不得把焦點小組模擬意見混入真實受訪者計數。

### 沒有真實問卷資料時

1. 由四位非主持人角色分別預測正向與反向回答。
2. 依矩陣產生每位角色的 KANO 代碼。
3. 彙整為「AI 焦點小組的 KANO 假設」，一律標示 `[暫定假設]`。
4. 不得宣稱這是顧客調查結果。
5. 對 P0 與高爭議功能產生成對問卷，列為下一步驗證。

## 五、剛性需求與理想需求係數

對每項功能統計 A、M、O、I、R、X 次數，令：

`N = A + M + O + I`

計算：

- `剛性需求 = (M + O) / (A + M + O + I)`
- `理想需求 = (A + O) / (A + M + O + I)`

剛性需求反映「缺少功能時造成不滿」的強度；理想需求反映「具備功能時創造滿意」的強度。一元品質 O 同時影響兩個方向，因此同時出現在兩個分子。

R 與 X 必須呈現，但不進入兩個公式的分母。若 `N = 0`，不得計算係數，應標示 `N/A` 並重新問卷。

### 四象限判讀

以 0.50 為兩軸切分點：

| 象限 | 條件 | 經營意義 | 預設決策 |
|---|---|---|---|
| Q1 | 剛性 ≥ 0.50、理想 ≥ 0.50 | 核心競爭需求 | P0，最先投入 |
| Q4 | 剛性 ≥ 0.50、理想 < 0.50 | 基本剛性需求 | P0，上線前完成 |
| Q2 | 剛性 < 0.50、理想 ≥ 0.50 | 理想／魅力需求 | P1，差異化階段 |
| Q3 | 剛性 < 0.50、理想 < 0.50 | 低效需求 | P2 或暫不投入 |

開發決策必須依象限分組呈現，順序為 Q1 → Q4 → Q2 → Q3，不只輸出一張平面排序表。

- **第一象限 Q1｜核心競爭需求：** P0，最先投入。
- **第四象限 Q4｜基本剛性需求：** P0，上線前完成。
- **第二象限 Q2｜理想／魅力需求：** P1，差異化階段。
- **第三象限 Q3｜低效需求：** P2 或暫不投入。

- Q1、Q4：先依剛性需求由高到低，再依理想需求由高到低。
- Q2：先依理想需求由高到低，再依剛性需求由高到低。
- Q3：若沒有其他使用者指定規則，並列為低優先。
- R 為最多票時：避免、移除、關閉或分眾，不作一般優先排序。
- X 為最多票時：修正題目並重測。

每一個功能在報告中都必須保留服務功能編號，例如 `F2｜完整總價與費用明細`。功能編號必須出現在功能展開、KANO 判定、係數表、四象限圖例、開發決策分組與最終下一步。

報告必須同時提供係數表與實際 KANO 四象限圖。圖的 x 軸是剛性需求，y 軸是理想需求；使用 F1、F2 等短 ID 標點，並在圖後提供功能名稱圖例。四象限圖必須以 SVG 原始碼直接內嵌在 Markdown 檔中，不能只用外部圖片連結。Mermaid 原始碼如需保留，只能用 `text` code block，不能用 fenced `mermaid` block。

## 六、報告要求

每項功能至少呈現：

- 報告整體至少 10 個可觀察、不可重複的服務功能；若服務旅程、角色、營運或風險需要更多功能，應增加 F11、F12 等，不得壓縮成模糊大功能。
- 正向問題或預測答案。
- 反向問題或預測答案。
- KANO 代碼與中文品質類型。
- 判定依據：真實問卷或 `[暫定假設]`。
- 四位角色各自的 A/M/O/I/R/X 判定與理由。
- A/M/O/I/R/X 分布或預測票數。
- 剛性需求與理想需求的代入算式及兩位小數結果。
- 四象限位置、重要性解讀與依象限產生的優先順序。
- 依第一象限、第四象限、第二象限、第三象限分組的開發決策。
- 不做的後果。
- MVP 驗收標準。
